gDownloader — O que falta pra superar o jDownloader
=====================================================
Data da análise: 2026-05-03
Branch analisada: development

Resumo do estado atual
----------------------
Já tem: 14 providers, fila SQLite persistente, WS de progresso, captcha (NoPecha + iframe),
rate-limit com countdown, mirror search, link grabber com cache, importação .dlc/.ccf/.rsdf,
Click'n'Load 2, monitor de clipboard, extração 7z/RAR,
verificação de hash MD5/SHA1/SHA256/CRC32 com .sfv, pausa/retomada, histórico, temas,
i18n (pt-BR/en-US), partes paralelas, speed limit global, auth helper via BrowserWindow
para hosts difíceis, downloader HTTP genérico com resume+segmentos, proxy/TOR/SOCKS5
(1 clique, só software, não afeta navegador), gráfico de velocidade em tempo real,
proteção contra disco cheio, pinned downloads, animações de estado, ErrorState padronizado,
comparador de mirrors com estimativa de velocidade.

Falta para virar um "jDownloader melhorado". Itens em ordem de impacto.

NOTA: A pasta browser-extension/ foi removida. O foco é nas camadas B e C.

PROMPT CODEX:
"Implementação em duas camadas paralelas:

CAMADA A — Proxy HTTP/HTTPS local com MITM (cobre apps que passam pelo proxy):
  Adicionar crate 'rcgen' + 'hudsucker' (proxy MITM em Rust) no backend.
  Módulo backend/src/proxy_intercept.rs:
    - Subir proxy em 127.0.0.1:9667 quando setting interceptProxyEnabled=true
    - Gerar CA root self-signed em userData/proxy-ca/ no primeiro start
      (rcgen::generate_simple_self_signed)
    - UI mostra botão 'Instalar certificado CA' que:
        macOS: abre Keychain Access via 'open -a Keychain\\ Access cert.pem'
        Windows: 'certutil -addstore Root cert.pem' (admin)
        Linux: copia pra /usr/local/share/ca-certificates/ + update-ca-certs
    - Inspecionar cada response: se Content-Disposition: attachment OU
      Content-Type batendo lista (zip, rar, mp4, mkv, iso, etc), interromper
      response no cliente, mandar pra fila do gDownloader e devolver pro
      cliente uma página 'Download enviado pro gDownloader'
    - Botão 'Configurar proxy do sistema' que abre as configurações de rede
      do SO para o usuário apontar manualmente para 127.0.0.1:9667

CAMADA B — Generic HTTP downloader que reproduz a request capturada:
  backend/src/providers/generic.rs (ampliar direct_http.rs existente):
    - Receber payload do interceptor com headers + cookies + UA + referer
    - Reproduzir requisição exata com headers preservados
    - Resume real (Range) testando via HEAD
    - Multi-part configurável (até parallelPartsPerDownload)
    - Validar Content-Length cumulativo
    - Ler Content-Disposition para filename inteligente

INTEGRAÇÃO:

  1. Parsear playlist M3U8/MPD e extrair lista de segmentos .ts/.m4s
  2. Baixar segmentos em paralelo (configurável, padrão 4) via direct_http
  3. Concatenar segmentos em ordem e muxar via ffmpeg -i concat:... -c copy
     (ffmpeg embutido em resources/ ou do PATH do sistema)
  4. Emitir progress_event a cada segmento concluído
  5. Para M3U8 com múltiplas qualidades (EXT-X-STREAM-INF), mostrar seletor
     de resolução no LinkGrabber antes de adicionar
  6. Para streams ao vivo: baixar segmentos novos até o usuário pausar/parar
Setting ffmpegPath sobrescreve localização do ffmpeg. Frontend: badge

44. SCHEDULER DE DOWNLOADS (agendar horário de início)
==========================================================
Permite enfileirar downloads para iniciar de madrugada (quando a banda está
livre) sem ter que ficar acordado.

PROMPT CODEX:
"Campo scheduled_at (INTEGER, timestamp Unix) na tabela downloads.
No POST /downloads, aceitar campo scheduledAt opcional. Se definido:
  - Status inicial é 'scheduled' (novo variant de DownloadStatus)
  - Task tokio a cada 30s verifica downloads com scheduled_at <= now() e
    os move para 'pending', disparando o scheduler normalmente
  - Endpoint PATCH /downloads/:id/schedule { scheduledAt: timestamp }
  - Frontend DownloadList.vue: na row com status scheduled mostra countdown
    'Começa em 2h 30m'. Botão 'Cancelar agendamento' reseta scheduled_at.
  - No LinkGrabber, botão 'Agendar' abre DateTimePicker (PrimeVue Calendar)
    ao lado do botão 'Adicionar'
  - Integração com item 14 (scheduler de banda): quando scheduled_at cai
    dentro de um slot de baixa velocidade, sugerir mover para o próximo
    slot de alta velocidade."
